# EX08 evidence and Frames

The four public operations share `SemanticExecutor.layer`, strict EX04 parsing, verified Presence, a 30-second request timeout, current World access and final Presence validation. Correction operations remain reserved. Runtime composition must provide the actual PostgreSQL layer, versioned `EvidenceObjectStore`, installation and admitted `DataPolicy`; this code supplies no fallback implementations.

Import validates the document and server policy before staging. A scoped SQL reservation records expected digest/length and expiration. The provider upload precedes the semantic transaction; its returned location is checked and recorded under a capture lock. Admission locks the World, operation and declared domains, then the capture. Source revision byte identity is immutable; exact dedup retains evidence and knowledge counters but records the new operation receipt. Receipt, claims, evidence, pins, counters and outbox commit together. Unused stages are cleanup candidates. Source labels are copied to evidence at admission, so later metadata never rewrites a historical Frame.

Inspect reads one native REPEATABLE READ snapshot, saves the private basis and visible Frame, and pins every source evidence. At most 200 claims are admitted to a Frame; querying 201 detects quota overflow instead of truncating knowledge. Comparable overlapping unequal amounts remain contested and unresolved. Equal or incomparable known claims remain set-valued; unknown amounts do not elect a winner. Every claim and Frame remains unverified. Historical inspection returns the original visible JSON after current authorization, without publishing private basis data.

OpenEvidence reads only the stored versioned object location, checks original bytes/digest/UTF-8 and rechecks current evidence location and authorization after provider I/O. Missing original content returns HistoricalContentUnavailable without mutating retained Frames.

`sweepExpiredCaptures(worldRef, cursor)` is a private maintenance function requiring trusted SQL/storage/policy composition. It processes at most 32 expired nonadmitted captures ordered by expiration and capture ID, returning a cursor for the next batch. The server must continue the page chain fairly and restart at null after its end. Captures with admitted evidence are excluded. Cleanup increments the capture fence before provider I/O, then marks removal only with the same fence. Removed rows remain tombstones and are revisited: an upload completing after an absence observation cannot regain admission and is removed on a later sweep. This worker does not erase admitted evidence or implement a future erasure profile.

Validation uses real restricted-role PostgreSQL and versioned S3 through the EX06/07 adapters. EX08 currently has four pure selection tests and four integration lifecycles: import/dedup/rollback, Frame history/open/cross-World denial, and expired capture/late upload cleanup, and the 200/201 claim boundary. Expired admitted captures remain protected from the orphan sweep. The existing nine EX05 integration tests also pass after mutation/transaction integration. Full HTTP/browser composition and independent acceptance are owned by subsequent segments; these private-context tests do not simulate authentication or count as end-to-end proof.
