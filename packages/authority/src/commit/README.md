# EX05 private authority boundary

`createPersonalWorld(context, request)` consumes a **verified private context**, the native Effect `SqlClient`, `AuthorityInstallation` and `DataPolicy`. It does not authenticate a browser. `SemanticExecutor.layer` in `semantic/executor.ts` is the ingress: strict EX04 byte parser, real `Presence.verify`, bounded context, explicit operation dispatch, result schema and quota, then fresh presence and World authorization before emission. `CreatePersonalWorld`, `ImportEvidence`, `Inspect` and `OpenEvidence` are active in this envelope; reserved correction requests remain Unsupported until EX13/14.

The server must provide `AuthorityInstallationSchema` with `cellId` UUID, `cellEpoch` canonical decimal string, `generationId` UUID and the SHA256 `releaseDigest` of the actual local release descriptor. There are no default IDs, release hash or privileged principal. The private owner seed in genesis initializes exactly the five EX02 domains and records the explicit data policy. `DataPolicy` is server configuration; client text is never a classification grant. An unsupported World policy blocks access before staging in EX08.

`bindWorldIntent(request)` uses the real EX04 intent digest. `commitMutation(context, bound, plan)` accepts the declared domains, an optional saved `InternalBasis` and the semantic SQL writer. The writer receives the fixed receipt ID and current domain cut; its requirements permit the native SQL service, not an object-store/provider service. Stage and other provider I/O precede this boundary. The writer returns `{ result, changedDomains }`; changed domains must be a subset of its already acquired domain locks. Only those counters advance, so a duplicate document with a fresh operation ID records its own receipt without invalidating unchanged knowledge. The result must match the operation's result tag and receipt ID. EX08 import is the first successful mutation consumer; EX05 separately tests the stale guard path.

Lock order is World head `FOR SHARE`, operation advisory lock, declared domains sorted lexically, then membership `FOR SHARE`. The scoped operation row, semantic changes, cut increments, receipt and pending outbox row commit together. Genesis uses the same `serializable` primitive with its pre-World operation key and deferrable FKs. SQL's `hashtextextended` is only an advisory lock bucket, not an intent hash: a collision can serialize unrelated work but cannot merge identities. Replay requires current access before comparing digests or reading retained output, and ingress verifies presence again before emission.

`serializable` uses native `SqlClient.withTransaction` and explicitly sets SERIALIZABLE. It permits two retries after the initial attempt, only for real `SerializationError` or `DeadlockError`. RC112's native client converts errors at COMMIT to defects (`SqlClient.ts`, `Effect.orDie(options.commit(conn))`). The boundary restores a typed SQL failure only for a cause containing exactly one SQL defect; mixed causes, non-SQL defects and interruptions remain unchanged. Constraint/connection/timeout failures are never retried. SQL details are converted to closed public errors after retry.

`validateBasis` compares the saved World/head/domain cut, membership revision, predicate fences, source revisions/digests and temporal windows. A clock sample is not compared by equality with the current clock. Commit windows are checked with PostgreSQL's current timestamp and the saved uncertainty. Current bases use `authority.basis.v2` / `authority.read-set.v2` and a six-domain cut including `identity`. Literal Inspect emits an empty identity dependency list; a `SubjectIdentityGraph` dependency binds canonical seeds/closure, interval, verified principal, purpose and the global identity revision. That dependency does not by itself deliver a resolver. Finer ACLs require revisiting the coarse fences before activation.

## Evidence and limits

Tests in `tests/integration/worlds/commit` use the actual EX06 adapter, restricted authority role, candidate DDL and invocation-owned temporary database. Their configuration hashes real synthetic fixture bytes and uses random IDs; it is test input, not a fabricated release admission. They call the explicit private verified-context boundary without mocking Presence. Authentication and end-to-end executor acceptance await EX09/EX10.

The tests cover duplicate concurrent genesis, retained replay, revocation, identical denial envelopes for another principal and an absent World, stale predicate/domain guard before writing, rollback at a real outbox constraint, a real deferred FK error at COMMIT, exactly three actual serialization conflicts, and a write-skew conflict emitted only at COMMIT followed by one successful retry. The write-skew test witnesses both completed SQL bodies and one persisted increment. A real division-by-zero SQL failure is attempted only once and returns no SQL detail.

The deferred-FK test first failed as an unhandled SQL defect (3 other transaction tests passed); after the narrow correction all four passed, followed by the COMMIT serialization witness. This is a driver compatibility finding, not permission to replace Effect's transaction implementation. The changed-document intent law is tested directly; its successful SQL mutation/replay path will be proved with the real EX08 importer. No storage, provider, authentication or complete D01 result is claimed by EX05 alone. Independent review and root composition remain required.

EX25 retains the exact unversioned five-domain schemas as `LegacyInternalBasis` / `LegacyReadSet`; `InternalBasis` decodes either retained version without promotion. The three correction handlers check authorized replay before loading Frames/Cases and retain the transactional replay check. A new act on a valid legacy basis returns `Stale` only after replay has been checked. Proposal scope and undo-target checks run after that guard; malformed stored data remains a closed error. Historical Frames, receipts, digests and source pins are not rewritten. New domain rows and migration/profile activation are integrator-owned prerequisites, not supplied by this module.
