# D01 values — EX04

`json.ts` exports `parseEnvelopeBytes` (1 MiB → `D01Request`), `parseDocumentBytes` (256 KiB → `ImportDocument`) and `parseDocumentText`. These return Effect with `InvalidInput | QuotaExceeded`; invalid Schema output becomes the closed public InvalidInput error. `parseJsonBytes` is the strict shared parser, with an explicit byte limit no larger than the envelope limit. HTTP must supply original bytes through `handleRaw`; it must not JSON.parse the envelope first.

Depth is counted from root 0, with child depth at most 32. Entries count every JSON value plus every object key, including the root; at most 10,000. Byte lengths count UTF-8, not UTF-16 characters. JSON whitespace is limited to space, tab, CR and LF. BOM, trailing content, malformed UTF-8, duplicate decoded keys and lone surrogates are rejected. Noncharacters are rejected per [RFC 7493 §2.1](https://www.rfc-editor.org/rfc/rfc7493.html#section-2.1). NUL is an **additional D01 restriction for PostgreSQL text/JSONB interoperability**, not a requirement of I-JSON. It is rejected in decoded keys and values, including inside document strings.

D01 uses the narrower safe-integer JSON-number subset: no fractional or exponent spelling, unsafe integer, infinity or underflow. Decimal amounts and revisions remain exact strings. Negative numeric zero canonicalizes to zero; decimal strings are not silently normalized. Plain UTF-8 and escaped equivalent characters decode identically, while distinct Unicode normalization forms stay distinct.

`canonical.ts` exports `intentDigest(SemanticRequest)`, `structuredDigest("read-set" | "correction-consequence", unknown)`, `canonicalJson(unknown)` and `digestBytes(Uint8Array)`. Canonical objects sort UTF-16 keys and preserve array order and exact strings. Unsupported prototypes, symbols, non-enumerable fields, accessors, sparse/extended arrays, cycles and non-JSON values fail. No getter or toJSON hook is invoked. Canonicalization has the same depth/entry limits and 1 MiB byte limit.

The semantic digest is SHA-256 over UTF-8 `zoen:d01:<domain>:v1\n` followed by canonical JSON. Intent includes the complete validated envelope, including operationId; original document string bytes remain significant. `intentDigest` validates the original JSON shape, decodes SemanticRequest, and strictly validates any inner import document before hashing. Callers of `structuredDigest` validate their ReadSet/CorrectionConsequence schema first. `digestBytes` hashes only the original evidence bytes, with no prefix. These are distinct domains; callers must not substitute one for another.

This module supplies pure parsing/hashing. It neither authorizes requests nor publishes correction operations. EX05 keeps the computed intention fixed across transaction retries; EX10 supplies the original HTTP bytes. Native Node `createHash` is used without a new dependency.

`amount.ts` consumes the public `ExactAmount` and `DecimalText` schemas. `addAmounts` preserves the greater input scale (`0.10 + 0.20 = 0.30`) and refuses currency mismatch or overflow. `compareAmounts` returns `Comparable` with order -1/0/1 or `NotComparable/CurrencyMismatch`; D01 has only the admitted currency unit set, with no implicit conversion factors. `normalizeDecimal` is an explicit operation, removing insignificant decimal zeros without scientific notation; it is not applied silently to imported bytes or intent digests. Arithmetic uses Effect `BigDecimal` and its bigint representation. The fixed textual renderer and output Schema enforce the D01 20 integer/18 fractional digit profile.

`roundAmount` requires both a target scale (0–18) and an explicit mode: reject, half-even, floor, ceil or to-zero. Reject refuses lost precision but permits removal of exact trailing zeros. Overflow fails even if rounding would otherwise succeed. No Number coercion of an amount occurs; numeric scale metadata does not carry monetary value.

`time.ts` consumes the existing civil/instant interval schemas. `intervalRelation` returns Overlapping, Disjoint, Unknown or NotComparable. Endpoints are half-open, so adjacent intervals are disjoint. Unknown never acquires the current time. Civil dates do not convert to instants. ID brands remain in the public contract; EX04 adds TS7 incompatibility assertions and UUID decode checks rather than another ID wrapper or generator.

Candidate verification on Node 24.20.0 / Effect 4.0.0-rc.112 / TS7: `pnpm test:unit EX04`, typecheck, lint and format checks. The initial escaped-NUL counterexample failed before the explicit PostgreSQL interoperability restriction was added; the same case now passes, along with NUL keys and inner documents. These are direct pure laws and parser boundaries, not evidence of authorization, storage or a published HTTP handler. W2 reviews the candidate independently; runtime consumption is tracked by EX05/EX08/EX10.
