# D01 S3 storage — EX07

`s3.ts` exports `layer(configuration: S3EvidenceConfig)`, a scoped Effect Layer for the private `EvidenceObjectStore` service. The production caller supplies every configuration field: existing bucket, endpoint URL, region, live realm, forcePathStyle, redacted access key/secret and connection/request timeouts. No credential chain, bucket creation, region, endpoint or test default is used implicitly. Bucket names in this initial profile use 3–63 lowercase letters/digits/hyphens. HTTP and HTTPS endpoints are explicit and cannot carry URL credentials, query, fragment or path prefix. Timeouts are bounded by the D01 30-second request profile. SDK retries are disabled (`maxAttempts: 1`). The S3 client is destroyed when its Layer scope closes.

The key is derived only inside the adapter from live realm, lowercase UUID World and capture IDs. `read` and `remove` require a validated internal ObjectLocation whose key exactly matches that scope. The adapter rejects evaluation for this initial profile; it does not configure a shared evaluation destination. Bucket policy, user authorization and SQL capture fencing are composition/executor responsibilities. Possession of an ObjectLocation is not public authority.

`stage` consumes the real Effect stream into one bounded allocation, requiring exactly the reserved byte count (1–262,144). It copies chunks and stops at the first excess; a truncated or failed stream cannot start a PUT. The SHA-256 from the real EX04 `digestBytes` must match before upload. The PUT supplies content length, SHA-256 checksum, fixed `application/json` metadata and `IfNoneMatch: "*"`. Success is followed by a bounded GET and complete byte verification. A real 412 is reconciled through that same GET, never by trusting metadata alone. Different bytes under the same capture key are not overwritten. A 409, timeout or other ambiguous response is Unavailable and leaves any object for the EX08 recovery/GC path; the adapter does not delete on an ambiguous failure.

`locate` accepts only the persisted reservation fields (World/realm, capture ID, expected digest and byte count). It derives the target privately, performs a real bounded GET, validates content type/length/hash and returns the observed object version, or NotFound. It never manufactures a successful location from a predicted key. EX08 may use it after claiming an expired capture under SQL fencing, including a reserved capture with no recorded upload response. A NotFound observation does not fence S3: a PUT can arrive later. EX08 owns durable tombstones and revisits; this adapter makes no claim of an S3 fencing primitive.

`read` honors an exact version when present, validates the returned version/content type/length and independently hashes bounded bytes. Unexpected SDK chunk types fail. The collector imposes its ceiling independently of response metadata, and the reader cancels on early failure/interruption. `remove` deletes only the validated internal key/version and is idempotent for an absent object. It does not decide whether a capture is pinned or eligible for deletion. Versioned and unversioned buckets are exercised; no presigned or public storage URL is produced.

Errors are the closed `StorageFailure` reasons InvalidInput, DigestMismatch, NotFound and Unavailable. Provider errors, credentials, endpoints and keys are not attached to them. JSON/document validation belongs to the executor's strict EX04 parser before semantic admission; staging bytes is not evidence admission. Pins, quarantine, expiry, GC claims and publication remain EX08.

Verification uses the actual installed AWS SDK and the local RustFS endpoint from the private `.env.infra`. Each test creates its own UUID bucket and removes only that bucket's objects/versions. Cases include byte round-trip, conditional replay/collision, truncated/failed/oversized/cancelled input, exact byte ceiling, realm/key rejection, altered bytes/content type, version-specific reads/removal, reservation-only locate and a real HTTP 403 from an invalid signing secret. The locate test discards a completed upload response; it does not claim to have injected a network-response loss. Two direct collector laws prove early stop and copying of reused source buffers. These checks do not prove SQL admission, IAM lifecycle, GC liveness or a public handler.
