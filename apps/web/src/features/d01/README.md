# Web D01 — EX12

Candidato implementado, aguardando composição e navegador reais. `feature.tsx` exporta `D01Feature` para o entrypoint reservado a root. Usa somente contratos públicos, React e Effect. A aplicação deve compartilhar origem com `/api/auth/*` e `/api/d01/execute`; `window.location.origin` define o destino. Fetch envia o cookie HttpOnly com `credentials: same-origin`, `cache: no-store`, sem redirect; o navegador define Origin em POST. Nenhuma senha/cookie vai a localStorage, sessionStorage, URL ou log.

`client.ts` usa HttpApiClient nativo para o executor e HttpClient para os quatro fluxos Better Auth publicados. `auth-form.tsx` separa o formulário, `requests.ts` prepara envelopes e `model.ts` mapeia resultados em props. `state.ts` contém estado efêmero de apresentação e a única borda ManagedRuntime; não interpreta valores, concede direitos ou reconcilia dados. Retry explícito conserva o mesmo request/operationId. Uma nova ação cria UUID pelo Web Crypto. Falha, interrupção ou timeout não são sucesso. A seleção de World é apenas uma referência fornecida pelo usuário; cada operação continua autorizada no servidor.

Cadastro/login, criação de World, importação, consulta por subjectKey e abertura de documento retido estão ligados a chamadas reais. O arquivo é decodificado como UTF-8 estrito, preservando BOM e texto original, sem JSON.parse; o parser do servidor continua capaz de recusar chaves duplicadas. O browser limita bytes antes da leitura; isso não substitui a validação no servidor. Decisões `scopedCorrections` aparecem por intervalo como anotação, sem substituir claims/selection automáticos; ações de correção dependem de EX14.

Login/logout também emitem aviso via BroadcastChannel da mesma origem, sem identidade, segredo ou payload; outras abas descartam suas views antes de revalidar sessão. Logout e mudança de World limpam dados privados e invalidam respostas em voo. pagehide/pageshow/popstate/visibilitychange descartam a leitura; o retorno verifica a sessão sem recuperar conteúdo antigo. A cada cinco segundos em página visível, a sessão é revalidada e um Frame exibido é reautorizado usando Inspect/atFrame; isso não cria novo corte. Revogação é observada na próxima resposta, não por uma assinatura instantânea do banco. Resultado de erro remove o Frame. Se logout falhar, a tela permanece vazia e o polling não reabre a sessão por conta própria.
