# Web D01 — EX12

Candidato implementado, aguardando composição e navegador reais. `feature.tsx` exporta `WorldsFeature` para o entrypoint reservado a root. Usa somente contratos públicos, React e Effect. A aplicação deve compartilhar origem com `/api/auth/*` e `/api/worlds/execute`; `window.location.origin` define o destino. Fetch envia o cookie HttpOnly com `credentials: same-origin`, `cache: no-store`, sem redirect; o navegador define Origin em POST. Nenhuma senha/cookie vai a localStorage, sessionStorage, URL ou log.

`client.ts` usa HttpApiClient nativo para o executor e HttpClient para os quatro fluxos Better Auth publicados. `auth-form.tsx` separa o formulário, `requests.ts` prepara envelopes e `model.ts` mapeia resultados em props. `state.ts` contém estado efêmero de apresentação e a única borda ManagedRuntime; não interpreta valores, concede direitos ou reconcilia dados. Retry explícito conserva o mesmo request/operationId. Uma nova ação cria UUID pelo Web Crypto. Falha, interrupção ou timeout não são sucesso. A seleção de World é apenas uma referência fornecida pelo usuário; cada operação continua autorizada no servidor.

Cadastro/login, criação de World, importação, consulta por subjectKey e abertura de documento retido estão ligados a chamadas reais. O arquivo é decodificado como UTF-8 estrito, preservando BOM e texto original, sem JSON.parse; o parser do servidor continua capaz de recusar chaves duplicadas. O browser limita bytes antes da leitura; isso não substitui a validação no servidor. Decisões `scopedCorrections` aparecem por intervalo como anotação, sem substituir claims/selection automáticos; ações de correção dependem de EX14.

Login/logout também emitem aviso via BroadcastChannel da mesma origem, sem identidade, segredo ou payload; outras abas descartam suas views antes de revalidar sessão. Logout e mudança de World limpam dados privados e invalidam respostas em voo. pagehide/pageshow/popstate/visibilitychange descartam a leitura; o retorno verifica a sessão sem recuperar conteúdo antigo. A cada cinco segundos em página visível, a sessão é revalidada e um Frame exibido é reautorizado usando Inspect/atFrame; isso não cria novo corte. Revogação é observada na próxima resposta, não por uma assinatura instantânea do banco. Resultado de erro remove o Frame. Se logout falhar, a tela permanece vazia e o polling não reabre a sessão por conta própria.

## EX19 CSV selection and browser proof

The real import surface has an explicit JSON/CSV choice for the next file batch. It defaults to JSON and resets when the session or World changes. JSON keeps the legacy `{ document }` envelope; CSV adds only `format: "worlds.csv.v1"`. The browser passes strict UTF-8 text unchanged, without parsing CSV or selecting a format from MIME, filename or contents. A retry retains the original SemanticRequest, including the document, format and operation ID, even if the next-batch selector changes after the failure. The existing evidence component renders returned CSV as React text and retains its logical record coordinates.

InvalidInput and QuotaExceeded now leave the file picker available, with the failure feedback and existing session preserved. The same failure path still clears Frame/evidence/proposal state. Unavailable and retryable infrastructure failures preserve their retry presentation; denied errors remain denied. This is presentation recovery, not a retry of a definitively rejected intention.

On 2026-09-05, the explicit-CSV unit test first failed against the builder from `e800cb4` because its envelope lacked the selector, then passed with `8562d28`. A separate real browser regression against the original CSV profile found the file picker absent after InvalidInput. With product fix `b8dcc29` integrated as `048d937` and root's fresh `csvv2` profile, the same picker assertion and subsequent valid CSV upload passed without reopening the World. Failure artifacts remain in the originating checkout; the baseline was not erased or reclassified.

Validation: four feature unit files / 13 tests passed; TypeScript and focused lint passed without warnings. All three journeys in `apps/web/test/integration/worlds-csv/csv.browser.spec.ts` passed against the real `csvv2` composition at `http://127.0.0.1:4312` (36.7 seconds). They exercised:

- Explicit wrong-format refusals in both directions, default/reset selection, and successful file selection after a definitive rejection.
- A real offline failure, then the same request's byte/format/operation-preserving retry, even after changing the next-batch selector.
- CLI CSV replay through stdin and a real file, preserving original CRLF, quoting, multiline text and final newline, plus default JSON replay. Each returned the same EvidenceImported result as the matching browser operation.
- OpenEvidence returning exact text/csv bytes, escaped script-like source text, logical record coordinates, second-principal denial and logout/back clearing.
- Mixed CSV/JSON divergence, correction, historical Frames, undo, unknown and Stale after another real import, without replacing original claims.

No backend response was intercepted or fabricated. The first browser attempt also exposed two harness errors: selecting a file while the old error view hid its picker, and a concurrent API call without the required Origin. The latter correctly returned 404. The final witness sends the real Origin and verifies picker recovery directly; it does not reopen the World to conceal that issue.

The independent review of root's CLI change `55917d9` found no issue in the format branch or existing raw input path. The real help includes choices and examples. An invalid format exited with code 2 and sanitized CLI_INPUT while stdin remained open, before the handler's input-read/network sequence.

Execution requires `ZOEN_TEST_CSV_WEB_URL` explicitly set to root's isolated CSV profile. `ZOEN_CLI_REVIEW_ENTRY` points to that build's CLI when run from another checkout. There is no fallback to a retained JSON profile. The existing acceptance glob discovers this witness; root's container verifier supplies the CSV URL for the new image. These browser results do not themselves prove a container run, SQL retention/cleanup, or disclosure behavior outside this scope.
