# Admission gate register — v4

All gates start unapproved. Code-ready is not provider/browser/operating qualification. The final intended scope requires its selected profiles and all applicable evidence; an unqualified candidate can only be replaced by reviewed change control. Declarative apps do not wait for the Rivet gate.

| Gate | Owner | Required evidence |
|---|---|---|
| G-APP-HOST | Application platform security | Real isolated guest origin/bridge/asset bootstrap, browser profile, backend containment, no shared private state, credential scrubbing, stream/export revocation and explicit guest disclosure mode. No blanket browser DLP assertion. |
| G-APP-LINKS | Identity/security and operations | Actual deployed host/TLS/DNS, private continuation login/session, recipient binding, preview/CSRF/open redirect/replay, shared-device logout and no third-party cookie dependence. Profile-bound browser traces and independent review. |
| G-CHANNELS | Channel/security owner | Real Telegram/email accounts; verified callback/signature/binding rules; delivery ambiguity; reply identity; consent/retention/abuse/cost controls per channel. |
| G-CLINICAL | Clinical/privacy accountable owner | Explicit permitted administrative versus clinical scope; lawful data use and contracts; access/retention/incidents; qualified review. No diagnostic/treatment authority implied by an administrative connector. |
| G-CLOUD-ENTERPRISE | Platform/security/operations owner | Named cloud region/account/profile; actual network/key/private-route tests; measured HA/restore/RPO/RTO; residency/erasure suppression; incident/on-call capacity and cost approvals. |
| G-CLOUD-PILOT | Pilot operations/privacy owner | Real shared pilot account/region; minimal isolation, backup/restore, erasure suppression and incident stop; owner/on-call; real-data permission; supported capacity and individually enabled providers. |
| G-COMPUTE | Compute/data security owner | Real remote/GPU execution account; private network/region/rights; bounded job/resource quota; cancellation/output admission/secret containment; measured workload cost. |
| G-EDGE | Fleet/security/customer owner | Supported hardware/OS/self-hosted profile; signed update/rollback; offline lease and clock failure; no duplicate World writer; erase/sync/recall/recovery; field support responsibility. |
| G-EFFECT | Provider/integration and security owner | Real provider sandbox or explicitly authorized safe test; idempotency/lookup/cancel callback behavior; observed unknown outcome recovery; narrow permit; allowed operation/risk/cost scope. |
| G-ENTERPRISE-IDP | Enterprise identity/security owner | Named SSO/SCIM provider and tenant; signed issuer/assertions; group mapping/revocation/replay/deprovision; workload identity isolation; break-glass policy with audit. |
| G-ENTERPRISE-SOURCES | Enterprise source/data owner | Named real Google/Microsoft/CRM/ERP/database/warehouse tenants; API/version/license; delta resets, pagination, rights/tombstone completeness, least privilege, lineage and operational resync evidence for each supported recipe. |
| G-FINAL | Product, architecture, security and operating owners | All 157 capabilities evaluated against the candidate; all intended provider/region/domain profiles qualified; no missing evidence; three-audience capstones; recovery/security/cost/accessibility evidence; independent final support matrix approval. |
| G-FINANCE-DATA | Market-data/license owner | Named vendors, instruments/venues, licenses/redistribution/purpose; provenance, freshness, corporate-action and symbol mapping; entitlement revocation; historical as-reported/restated coverage. |
| G-FINANCE-EXECUTION | Qualified financial/legal/provider owner | Exact broker/custodian/venue/account/jurisdiction; provider certification; order/fill/bust/cancel/allocation/custody tests; supervision/retention; operating authorization and incident responsibility. |
| G-FINANCE-RISK | Qualified risk/model owner | Permitted decision scope; versioned models, validation/limitations; point-in-time data and entitlement; scenario stress/illiquidity/freshness checks; independent model approval. |
| G-MARKETPLACE | Product/legal/security owner | Publisher identity/provenance; license and permitted distribution/use; signing/recall; dependency upgrade/rights expansion; billing/refund/support scope before commercial activation. |
| G-MCP-APPS | Client platform security | Exact real host and MCP Apps dialect, resource/tool session constraints, current permission checks, user confirmations, information-flow mode and tested safe text/protected-link fallback. |
| G-MODEL | Model/security owner | Named provider/API and approved data region/retention; exact model/tool contract; prompt injection and grounding evaluation; usage/cost limits; secret handling and incident stop. |
| G-OPERATIONS | Operations/security/customer owner | Measured workload/cost envelope; tenant fairness and quota; incident and recovery drills; support access controls; auditor evidence export; explicit SLO/support responsibility. |
| G-RIVET-DYNAMIC | Runtime platform and security | Exact actual Dynamic Apps Core lock, observed deploy semantics, immutable nonpublic slot/public-binding separation, hosted isolation, configuration/credentials, state partition, recall/recovery and measured profile limits. Failure keeps adapter disabled; replacement needs reviewed ADR. |
| G-RUNNER | Platform security owner | Exact actual isolation profile; host/metadata/socket/egress probes; credential broker; CPU/memory/time/output limits; image provenance, artifact recall and guest cleanup. |
| G-SOURCE | Data/source owner | Authorized source account; OAuth/scope/refresh; complete pagination/tombstone/ACL/freshness contract; rights/license; quarantine/drift/deletion and resync evidence. |
| G-USABILITY | Product/accessibility owner | Consented usability sessions for target audiences; keyboard/screen-reader/200% zoom/shared-device checks; comprehension of uncertainty and approvals; recorded issues and disposition. |
| G-WHATSAPP | Channel/business-policy owner | Actual authorized business number/account; current provider and WhatsApp terms/use permission; consent/templates/window handling; real ingress verification/delivery/replay; cost and data handling; approved operating scope. |
